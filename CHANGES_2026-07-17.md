# Proxmox Changes — 2026-07-17

## 13:xx — Fix 1: Disable Enterprise APT Repo (home1 & home2)

**Problem:** `pve-enterprise.sources` (DEB822 format) was active on both nodes despite no subscription key. The older `pve-enterprise.list` was already commented out, but this newer file was still causing 401 errors on every `apt-get update`.

**Nodes affected:** home1 (10.0.0.91), home2 (10.0.0.92)

**Change:** Added `Enabled: no` to `/etc/apt/sources.list.d/pve-enterprise.sources` on both nodes.

```
# home1 & home2 — before
Types: deb
URIs: https://enterprise.proxmox.com/debian/pve
Suites: trixie
Components: pve-enterprise
Signed-By: /usr/share/keyrings/proxmox-archive-keyring.gpg

# home1 & home2 — after
Enabled: no
Types: deb
URIs: https://enterprise.proxmox.com/debian/pve
Suites: trixie
Components: pve-enterprise
Signed-By: /usr/share/keyrings/proxmox-archive-keyring.gpg
```

**Verified:** `apt-get update` runs clean on both nodes (no Err: lines).

## 13:xx — Fix 2: Create Automated Backup Job

**Problem:** No backup jobs were configured (`vzdump.cron` empty, cluster backup count = 0).

**Change:** Created cluster-wide backup job via `pvesh create /cluster/backup`.

| Setting | Value |
|---------|-------|
| Schedule | Every Sunday at 02:00 |
| VMs included | 100 (truenas), 103 (haos13.1), 104 (workflows) |
| Storage | `truenas` (NFS, 940 GB) |
| Mode | Snapshot |
| Compression | zstd |
| Retention | Keep last 4 |
| Notifications | On failure |

**Config written to:** `/etc/pve/jobs.cfg` (cluster-replicated)

```
vzdump: 71a1064e-ff90-4f50-be23-ff30e26dc490
    schedule sun 02:00
    compress zstd
    enabled 1
    mailnotification failure
    mode snapshot
    notes-template {{guestname}}
    prune-backups keep-last=4
    storage truenas
    vmid 100,103,104
```

**First run:** 2026-07-20 02:00

## 13:xx — Fix 3: CT 104 (workflows) — Disk Freed

**Node:** home2 (10.0.0.92)

**Problem:** Disk at 94% — 745 MB free of 12 GB.

**Root cause:** systemd journal had grown to 981 MB with no size cap.

**Changes made inside container:**
1. `journalctl --vacuum-size=100M` — trimmed journal from 981 MB → 100 MB (freed ~881 MB)
2. `apt-get clean` — cleared apt package cache
3. `docker container prune -f` — removed exited containers
4. `docker image prune -f` — removed dangling image layers

**Result:** 11 GB → 6.2 GB used — disk now at **56%**, 3.8 GB free

## 13:xx — Fix 4: CT 109 (tools) — Disk Freed

**Node:** home4 (10.0.0.94)

**Problem:** Disk at 91% — 539 MB free of 6 GB.

**Root cause:** Two stale Docker images (newer versions pulled but not deployed), bloated journal, and apt cache.

**Changes made inside container:**
1. `docker container prune -f` — removed exited openbooks container
2. `docker rmi amir20/dozzle:v10.6.7` — removed unused newer image (68 MB)
3. `docker rmi crazymax/diun:4.33.0` — removed unused newer image (61 MB)
4. `journalctl --vacuum-size=100M` — trimmed journal from 412 MB → 100 MB
5. `apt-get clean` — cleared apt package cache

**Result:** 5.1 GB → 4.4 GB used — disk now at **80%**, 1.2 GB free

**Note:** Stirling PDF image (2.27 GB) is the dominant consumer and is actively running — not touched.
